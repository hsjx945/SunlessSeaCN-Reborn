# macOS v6.0.5 执行计划

状态：实现和真实安装已完成，独立验收中。Windows 保持 v6.0.4；本计划只生成 macOS v6.0.5，不创建 tag 或 GitHub Release。

## 实现

1. 从 tinygrox 锁定源码构建不依赖 BepInEx 的 `SunlessSeaChineseTranslation.dll`。
2. 提供幂等 `Bootstrap.Init()`，加载包内 Images/Data 后执行 `Harmony.PatchAll()`。
3. 用 Mono.Cecil 验证并在当前 `Sunless.Game.dll` 的唯一 `TitleScreenInit.Start` 入口注入调用；原候选 `IntroScript.PlayEAWarning` 在正常启动主菜单前没有可靠到达，已弃用。
4. 对原始与目标 DLL 生成 bsdiff；安装包只携带差分、bootstrap、Harmony、资源和 addon。
5. 在隔离 app clone 中完成程序集、签名、启动和中文 UI 验收，再对真实游戏执行同一事务。
6. 修复 Bash 3.2 安装/卸载、锁、临时 manifest、重复安装和回滚，生成 macOS-only v6.0.5 ZIP。

## 门禁

- 原始 DLL SHA-256 必须为 `b7d5df522b8ae7c1ee4913b283586fc4d823f735159bf00753f42ce4a86474f0`。
- 注入目标必须存在且唯一；所有 Harmony target 在构建/启动中不得抛异常。
- 修改 sealed resource 后只做可审计的 ad-hoc 重签；`codesign --verify --deep --strict` 必须通过。
- 真实主菜单已观察到中文；运行时仓库探针已确认 addon 事件 143942 为中文。事件 144628 的数据标题为“创建你的船长”，但 Unity 全屏不接受当前 UI 自动化点击，仍需用户实际点击新游戏补一张剧情界面截图。
- 安装、重复安装、卸载恢复通过；存档 hash/size/mtime 不变。
- Windows 版本常量和构建入口保持 v6.0.4；本轮不生成、不发布 Windows 资产。

## 回滚

安装前备份 `Sunless.Game.dll` 和签名相关文件；所有写入先在同卷临时文件完成并校验。任一门禁失败即恢复备份，不留下完成态 manifest。卸载只删除 hash 与 manifest 记录一致的文件，并恢复原始 DLL/签名；用户修改过的文件保留并报告。
