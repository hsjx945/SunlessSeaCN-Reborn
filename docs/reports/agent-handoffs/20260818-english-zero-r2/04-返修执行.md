## 根因与边界

- 真实游戏 `2.3.0.22` 与服务端要求 `2.2.4.3141` 在第二段已可判定为前者更新；原算法删除点号后比较 `23022 < 2243141`，产生“需要更新到最新”的误报。
- `GameVersion` 缺失时原方法把本地内容日期设为 `DateTime.MinValue`，即使本机内置内容与服务端 `201710261506` 平级也会进入更新检查；本修复仅以内置常量填补缺失 key，不写 key、不跳过真正的新内容。
- 服务端下载、JSON 反序列化、已有 key 的非法日期和版本解析失败仍走原游戏逻辑；没有无条件 `true` 或吞掉网络错误。

## 经验候选

- 症状：最新版英文游戏无提示，中文补丁进入账号管理/右下角后提示“需要游戏版本为最新”。
- 原始证据：实机 `GameProvider.VERSION_NUMBER=2.3.0.22`，服务端 `SoftwareRequired=2.2.4.3141`，原 `GetVersionNumber` 删除点号后形成错误整数序；`PlayerPrefs.GameVersion` 缺失且内置/服务端内容版本均为 `201710261506`。
- 已验证根因：版本号被当作十进制整数比较；缺失内容 key 使用最小日期。
- 可复用修复：版本号按数字段逐段比较；只有缺失 key 才从内置内容版本生成基准；解析失败保持原逻辑。
- 验证结果：纯 C# harness、静态补丁、完整 macOS 包测试均通过。
- 适用范围：当前 Steam BuildID `24437295`、Unity 6 Mono `Sunless.Game.dll` 的 macOS 静态补丁。
- 反例：新 BuildID 或服务端字段格式变化时不得沿用 hash/方法签名假设；需重新构建并验证。
- 建议落点：项目版本兼容记录与 `tests/test_macos_static_ui.sh` 回归门禁；暂不晋升全局规则。
