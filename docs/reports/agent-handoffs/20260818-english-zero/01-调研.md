## 事实

1. 截图漏翻来自 `Sunless.Game.UI.Menus.Options.VideoOptionsPanel.WarnAboutResolution()`，其构造 `AlertDialog` 时传入 `Warning` 与完整分辨率提示。现有 `SS_AlertDialog` 只替换 `Continue` 按钮；`SS_VideoOptionsPanel` 只处理面板静态标签。
2. 其他明确未覆盖弹窗：`LatestNews.WarnAndVisitURL`、`CharacterRepository.LoadGame` 主存档与备份同时损坏分支、`MenuProvider.WarningErrorMessage` 的服务器连接错误、`Fatal Error` 通用标题。
3. v6.0.5 `entities/events.json` 静态候选：排除已归档分支、显然指令和常见开发标记后，仍有 112 个英文 `Name` 记录，101 个不重复文本：6 个顶层事件名、17 个未归档选项名、89 个结果事件名。这是候选上限，仍含个别测试/内部路由；普通剧情 `Description` 没有发现同等规模的英文段落残留。
4. 原始 ASCII 扫描命中 4,806 个值，绝大多数是内部对象名、资源名、`Notes`、Deck 枚举和技术指令；不得为追求“字节级零英文”而批量替换。
5. 繁中项目 `https://github.com/kaosensei/sunless-sea-zh-tw` 锁定 `124a8e440a5bc6f4cebdf5791b92067d4aa17971`，实际数据为 872 个 events，提供可用的事件 ID/可见性和术语参考。译文文本明确是 CC BY-NC-SA 4.0；当前简中 addon 未发现独立 LICENSE，不应将繁中译文无区分合并并声称整体可重新许可。实现优先使用事件 ID 定位并对英文原文独立翻译；若复用具体繁中译文，必须单独标注来源并随包提供 CC BY-NC-SA 4.0 归属。
6. 当前构建脚本每次从锁定的 v6.0.4 ZIP 拷贝 addon 到 `build/`；直接改 `build/` 或 `dist/` 会在下次打包丢失，必须建立仓库内可追踪 overlay/生成步骤。

## 测试 oracle 要求

- 扫描仅针对已定义的玩家可见路径/字段，允许显式 allowlist 保留品牌、人名、缩写和技术字段。
- overlay 必须同时校验 ID、旧英文值和新中文值，防止游戏更新后静默错配。
- UI 回归必须验证目标方法中英文常量被 Harmony 覆盖，并在真实 UI 触发分辨率警告。
- 重打 ZIP 后扫描最终 payload，不只扫描源文件。

## 经验候选

- 症状：手改构建产物后当次有效，重打包消失。证据：`build-macos-static-ui.sh` 每次解压 v6.0.4 payload 并整树复制 addon。根因：缺少持久 overlay。修复候选：带旧值断言的 ID overlay + 最终 payload 扫描。本任务验证后再决定是否写入项目排错文档。
