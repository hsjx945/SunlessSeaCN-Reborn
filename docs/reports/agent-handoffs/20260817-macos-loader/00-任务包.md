# macOS loader 修复任务包

## 目标

基于仓库 tag `v6.0.4`（`69dba91498b9b51caa441e576c58bc9452b5c295`）只修复 macOS 汉化，在真实 Steam Sunless Sea 中观察中文 UI，再生成后续 macOS 安装包；Windows 6.0.4 不做任何修改。

## 已确认事实

- v6.0.4 的 macOS 安装器仍含 Bash 3.2 `local rel=... dest=...` nounset 缺陷。
- 插件只允许 `Sunless Sea.exe`，实际 macOS 进程名为 `Sunless Sea`。
- 修复安装器、插件字符串、绝对 Doorstop 路径并强制 x86_64 后，Doorstop dylib 会映射，但没有 BepInEx 日志；显式指定 `libmonobdwgc-2.0.dylib` 仍失败。
- 游戏与 Mono 为 universal；正式兼容路径先验收 Rosetta x86_64。
- GitHub TLS 故障是 Clash 上游的瞬时连接中断；代理和证书当前正常，v6.0.4 已成功浅克隆。

## 当前阶段

先实现仅用于诊断的 x86_64 native bridge：constructor 启动单一后台线程，轮询游戏已初始化的 Mono root domain，在同一 Mono 线程附加后加载 `BepInEx.Preloader.dll` 并调用 `Doorstop.Entrypoint.Start()`。诊断时只能注入 bridge，禁止同时注入 Doorstop。

允许新增：

- `native/macos/sunlesssea_mono_bridge.c`
- `scripts/build-macos-bridge.sh`
- `scripts/run-macos-bridge-diagnostic.sh`
- `tests/test_macos_bridge_artifact.sh`
- 本目录阶段交接记录

禁止：

- 修改 Windows 文件或包；修改游戏 `.app/Contents`；修改翻译 JSON、图片、存档；发布 release/tag；双重注入 Doorstop；未经真实 UI 验收把 bridge 放进正式包。

## 验收门禁

- clang `-Wall -Wextra -Werror` 构建 x86_64，ad-hoc codesign，依赖仅系统库。
- bridge 日志记录 constructor、Mono/domain、assembly、method、invoke/exception/timeout。
- 真实运行产生 BepInEx chainloader 与中文插件日志，且实际游戏窗口出现中文。
- 不崩溃、不重复启动 Preloader、存档内容不变、测试后无残留进程。

## 失败边界

首次轮询方案若 root domain/Mono 超时，只保留证据并返回；不得在同一个执行代理中扩张为 interpose/fishhook 或修改游戏本体。
